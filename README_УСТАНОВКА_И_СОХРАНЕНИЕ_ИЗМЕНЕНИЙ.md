# Mirror-info — актуальное состояние и безопасная работа с проектом

Документ описывает код ветки `feature/preserve-format-image-translation-main`. Он не является подтверждением того, что эта ветка уже опубликована на production.

## Что находится в проекте

- `index.html`, CSS и клиентские скрипты — интерфейс переводчика, загрузка документов, калькулятор и форма заявки.
- `translate-core.js` — извлечение и обработка содержимого DOCX, EPUB, FB2, PDF, RTF, TXT и изображений с OCR. Поддержка форматов различается: извлечение текста не означает полного сохранения исходного оформления.
- `document-counter.js` — подсчёт символов, слов и расчётных страниц; получает события о загрузке/очистке документа. Для PDF передаётся физическое число страниц, когда оно доступно.
- `calculator.js` — предварительный расчёт по действующим в коде ставкам и множителям. Это не утверждённая полная региональная тарифная матрица.
- `functions/api/orders.js` и `functions/api/admin/*` — серверные endpoints Cloudflare Pages Functions.
- `schema.sql` — схема D1; `wrangler.toml` — конфигурация Cloudflare Pages/Workers.
- `book.html` — встроенная читалка; её локальные настройки и прогресс не равны облачной синхронизации.

## Обработка документов: важные границы

- DOCX: перевод выполняется в структуре OOXML с проверками состава частей пакета и связанных ресурсов. Это снижает риск потери элементов, но не гарантирует пиксельное совпадение с Word для любых документов.
- EPUB: текстовые части архива переводятся с проверками структуры и SHA-256 нетекстовых ресурсов. Проверка хешей подтверждает неизменность ресурсов, но не доказывает одинаковое отображение во всех читалках.
- FB2: XML-структура и нетекстовые ресурсы проходят проверки; реальные книги с разными кодировками и особенностями XML всё ещё нужны для расширенного QA.
- PDF: текстовые слои и OCR обрабатываются отдельно. Пересборка страниц может менять векторные элементы, формы, подписи, доступность и некоторые интерактивные возможности. Не обещайте полное сохранение сложного PDF.
- RTF и обычный текст: извлечение/перевод текста не эквивалентны полноценному редактированию с сохранением всех исходных стилей.
- OCR изображений и сканов зависит от качества, языка, разрешения и контраста; восстановление фона и шрифтов приблизительное.

Перед коммерческим использованием проверяйте реальные файлы разных типов, размеров, языков и программ просмотра. Синтетические CI-тесты не заменяют пользовательские документы.

## Статистика документа

Загрузчик отправляет событие `mirror-info:document-loaded` после успешного извлечения текста и `mirror-info:document-cleared` при сбросе выбора. В событии загрузки передаются текст и имя файла; для PDF дополнительно передаётся фактическое количество страниц, если оно было определено PDF.js.

Проверяйте статистику после открытия файла, замены файла, очистки, ошибки чтения и ручного ввода. Для форматов, где число физических страниц не имеет однозначного смысла (например, EPUB/FB2), показывайте расчётные страницы, а не выдуманное физическое число.

## Заявки, D1 и админка

- Форма отправляет заявки через Pages Function; серверная сторона валидирует входные данные, применяет ограничение частоты и сохраняет заявку в D1.
- Уведомления Telegram/Resend работают только при наличии корректно заданных Cloudflare secrets.
- Админские endpoints должны быть закрыты Cloudflare Access. `orders.js` выполняет проверку подписи и claims JWT; endpoint определения Telegram chat ID использует ту же проверку, а не простое наличие заголовка.
- В Cloudflare Access ограничьте `/admin.html` и весь `/api/admin/*` только нужными identity/email. Включите MFA.
- Не добавляйте токены, пароли, API keys или значения секретов в HTML, JavaScript, README, коммиты и скриншоты.

Защита маршрута не заменяет настройку Access policies на стороне Cloudflare. Проверяйте API без авторизации, с неверным/истёкшим токеном и после входа администратора.

## Cloudflare и D1: осторожная сверка

В `wrangler.toml` задан binding `DB`, имя базы и database ID. Перед любыми изменениями сверьте их с существующей D1 database и Pages binding в панели Cloudflare. Не создавайте новую базу только потому, что имя в документации отличается. Не применяйте схему повторно вслепую и сначала сделайте резервную копию данных.

Изменение `wrangler.toml`, bindings или secrets само по себе не обновляет уже опубликованный сайт. Для применения конфигурации потребуется отдельное развертывание, которое должно выполняться только после проверки и явного разрешения владельца.

## Большие PDF

`PDF-LARGE-FILES-ARCHITECTURE.md` описывает целевую архитектуру пакетной обработки с временным хранилищем и короткоживущими разрешениями. Документ архитектуры не означает, что R2 upload, очередь заданий, merge endpoint и очистка временных файлов уже развёрнуты. Не увеличивайте лимиты монолитной обработки вместо реализации архитектуры.

## Калькулятор и тарифы

Текущие ставки в коде — техническая конфигурация, а не утверждённый полный прайс. Нельзя автоматически подставлять одну ставку DOCX для PDF/EPUB/FB2 или придумывать цены для регионов. Полная матрица форматов, услуг, валют, регионов, срочности, нотариального заверения, скидок и минимальной стоимости должна быть согласована отдельно и храниться в управляемой конфигурации.

## Личный кабинет и читалка

История и настройки, которые хранятся в `localStorage`, привязаны к конкретному браузеру/устройству и могут исчезнуть при очистке данных. Это не полноценная учётная запись и не облачная синхронизация. Для общей истории заказов, квот и библиотеки требуется серверная идентификация пользователя и защищённые API.

## Безопасный порядок работы

1. Разрабатывать и проверять изменения в feature-ветке и открытом PR.
2. Проверять diff и запускать относящиеся к изменённым файлам CI workflows.
3. Проверять реальные документы на копиях, не на единственных оригиналах.
4. Не менять production bindings, D1, secrets и Cloudflare Access в рамках обычного аудита.
5. Не сливать PR и не запускать production deploy без отдельного явного разрешения.
6. После каждого этапа записывать SHA коммита и фактические результаты CI. Не называть незавершённые проверки успешными.

## Что остаётся отдельной работой

- Полные реальные регрессионные тесты DOCX/EPUB/FB2/PDF/OCR.
- Синхронизация личного кабинета и заказов с серверной учётной записью.
- Управляемая тарифная матрица и полноценные роли/отчёты админки.
- Облачная библиотека и синхронизация прогресса читалки.
- Реализация архитектуры больших PDF с R2 и пакетной обработкой.
- Политика хранения/удаления персональных данных и журнал административных действий.
